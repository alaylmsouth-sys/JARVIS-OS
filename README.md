# JARVIS OS

> **AI 작업을 준비하고, 사람은 중요한 결정만 최종 승인하는 개인 운영 대시보드**입니다.

JARVIS OS는 프로젝트 진행 상황, 영상 승인, AI 연결 상태, 재무·자산 기록을 한곳에서 확인하도록 돕습니다. 처음에는 모든 기능을 설정할 필요가 없습니다. **AI 키나 외부 서비스 계정 없이도 대시보드를 둘러보고, 샘플 데이터와 안전한 dry-run을 사용할 수 있습니다.**

## 가장 먼저 할 일

**Python 3.10 이상**만 설치되어 있으면 됩니다. `run` 파일은 최초 한 번 필요한 라이브러리와 전용 실행 환경을 자동으로 준비합니다. 처음 실행은 인터넷 연결 상태에 따라 몇 분 걸릴 수 있습니다. 실행 창은 대시보드를 사용하는 동안 닫지 마세요.

| 운영체제 | 1단계 | 2단계 | 대시보드 |
| --- | --- | --- | --- |
| Windows | 프로젝트 폴더를 엽니다. | `run.bat`를 더블클릭합니다. | `http://127.0.0.1:8000` |
| macOS / Linux | 터미널에서 프로젝트 폴더로 이동합니다. | `chmod +x run.sh && ./run.sh`를 실행합니다. | `http://127.0.0.1:8000` |

화면에 `JARVIS OS를 시작합니다`와 주소가 보이면 브라우저에서 위 주소를 엽니다. 종료하려면 실행 중인 창에서 `Ctrl+C`를 누르세요. 다음에 다시 사용할 때도 같은 `run` 파일을 실행하면 됩니다.

## 첫 화면에서는 이렇게 시작하세요

처음 열리는 **오늘의 시작** 화면에서 아래 세 가지 중 하나만 선택하면 됩니다. 다른 메뉴는 당장 열어보지 않아도 됩니다.

| 지금 하려는 일 | 선택할 메뉴 | 할 수 있는 일 |
| --- | --- | --- |
| 오늘 해야 할 일 확인 | `오늘의 시작` | 진행률과 남은 작업을 확인하고 완료 표시를 합니다. |
| 영상을 확인하고 승인 | `영상·승인 관리` | 영상 품질을 검토한 뒤 승인·반려·재생성을 선택합니다. 업로드는 자동으로 실행되지 않습니다. |
| AI 키·데이터·백업 상태 점검 | `AI·시스템 상태` | 연결 상태를 확인하고 필요한 설정만 준비합니다. |
| 투자·재무 기록 확인 | `업무·자산 관리` | 보유 자산·수익·비용을 기록하고 확인합니다. 주문을 실행하지 않습니다. |

> 외부 AI 호출, 영상 업로드, 투자 주문처럼 중요한 작업은 항상 사용자의 명시적 확인이 필요합니다. 연결되지 않은 항목은 오류가 아니라 **설정 전 대기 상태**로 표시됩니다.

## 자주 막히는 경우

| 증상 | 먼저 해볼 일 |
| --- | --- |
| Windows에서 `run.bat`를 눌렀는데 창이 바로 닫힙니다. | Python 3.10 이상을 설치한 뒤 다시 실행하세요. 설치할 때 `Add Python to PATH`를 선택하면 도움이 됩니다. |
| macOS/Linux에서 권한 오류가 납니다. | 프로젝트 폴더에서 `chmod +x run.sh`를 한 번 실행한 뒤 다시 `./run.sh`를 실행하세요. |
| 브라우저에서 주소가 열리지 않습니다. | 실행 창을 닫지 않았는지 확인하고, `JARVIS OS를 시작합니다`라는 문구가 나온 뒤 주소를 다시 여세요. |
| `8000` 포트가 이미 사용 중이라는 메시지가 나옵니다. | 기존에 실행 중인 JARVIS OS 창을 `Ctrl+C`로 종료한 뒤 다시 실행하세요. |

더 자세한 초기 설정과 안전한 테스트는 [실행 가이드](docs/QUICKSTART.md)를 참고하세요.

## 검증

초기 실행 시 대시보드가 `memory/templates/`의 기본 파일을 `memory/`에 한 번만 생성하며, 기존 개인 데이터는 덮어쓰지 않습니다. 자동 검증은 다음 명령으로 실행합니다.

```bash
python -m pytest -q
```

영상 파이프라인의 구조 검증은 외부 AI·TTS·영상 생성 서비스를 호출하지 않도록 `--dry-run`에서 placeholder 영상과 무음 트랙을 강제합니다.

```bash
python -m video.pipeline "테스트 주제" --dry-run
```

## 현재 상태 (v1.0.0-rc — 5개 센터 큰 틀 완성)

- ✅ AI Project Manager: 진행률, 단계별 작업, 오늘의 우선순위
- ✅ AI Scoreboard: AI 직원 성적표 (아직 미연결 상태 표시)
- ✅ CEO 결재함: 승인/반려/재생성 (샘플 1건 포함)
- ✅ AI Router: 작업→AI 라우팅, 사용료 기록, dry-run (2단계)
- ✅ 영상 파이프라인: 대본→장면→영상→자막→썸네일→품질검사→결재함 (3단계, dry-run 자동 검증 완료·실AI 연동 검증 대기)
- ✅ 영상 성과 분석: 조회수/좋아요/댓글/시청시간 스냅샷 + 증감 추적 (실API 검증 대기)
- ✅ AI 관리센터: 역할별 배정/키/사용량/경고 (12단계)
- ✅ 시스템센터: 자가 점검 — 환경/인증/무결성/백업 (13단계)
- ⬜ 실환경 검증 5종: docs/14 표 참고 (키 설정 → 인증 → 업로드 1건)

## 폴더 구조

```
JARVIS-OS/
├── dashboard/   # 웹 대시보드 (FastAPI + HTML)
├── brain/       # 핵심 로직 (project_manager 등)
├── router/      # (2단계) AI Router
├── agents/      # (3단계~) AI 직원들
├── finance/     # (4단계) 재무센터
├── video/       # (3단계) 영상 파이프라인
├── memory/      # 내 데이터 (git 추적 안 함) — templates/에서 자동 생성
│   └── templates/ # 초기 템플릿 (저장소에 포함)
├── security/    # (추후) 백업/보안
├── plugins/
├── tests/
└── docs/        # 설계 문서
```

## 핵심 원칙

1. 모든 영상은 업로드 전에 반드시 CEO가 최종 검토하고 승인한다.
2. 중요한 작업(업로드, 투자 주문, 세금 신고 등)은 항상 사람의 최종 승인을 거친다.
3. JARVIS는 준비와 추천은 자동화하되, 중요한 결정은 사람이 내린다.
4. 모든 상태는 memory/ 폴더의 파일에 저장한다 (대화 세션에 의존하지 않음).
5. 코드는 공개, 내 데이터는 비공개: memory/*.json은 git에 올리지 않고 `./backup.sh`로 비공개 저장소(JARVIS-DATA)에 백업한다.
